# 0003 — pnpm 11, with one catalog and a release-age delay

- **Status:** accepted (2026-09-29)
- **Applies to:** `pnpm-workspace.yaml`, `package.json#packageManager`, every `package.json`

## Context

Agents add imports freely. In a hoisted `node_modules` an import of a package the project never
declared still works, until a deploy or another machine proves otherwise. In a monorepo, each
package can also drift to its own version of a shared dependency (two Reacts, two routers, two
copies of graphql that break `instanceof`). And installing whatever was published a minute ago is
how a compromised release reaches you.

## Decision

- **pnpm 11** (`packageManager: pnpm@11.27.1`, also in `.prototools` and the Dockerfiles;
  `pnpm check` fails when they disagree: `tools/check-versions.mjs`). The only package manager:
  agents are told never to use npm, yarn or npx, and `npx` is denied.
- **Strict, isolated installs**: a package resolves only what its own `package.json` declares.
- **One catalog** (`pnpm-workspace.yaml`): every external dependency is `"catalog:"` (workspace
  packages are `workspace:*`), so the workspace has one version of each; `catalogMode: prefer`
  makes `pnpm add` reuse it. Versions are pinned exactly where compatibility is tight or a tool is
  pre-1.0, with the reason next to the entry.
- **`minimumReleaseAge: 1440`**: no version younger than 24 hours is installed.
- **`allowBuilds`**: only the listed packages (esbuild, lefthook, nx) may run install scripts.
- **`overrides`** pin `graphql` to one copy for every package (Pothos and Yoga are built for 16).
- Adding a dependency (`pnpm add <pkg> --filter <project>`) asks a human first, like `pnpm remove`
  and `pnpm dlx` ([agents.md](../agents.md#permissions)).

## Consequences

- An undeclared import fails locally, at once, rather than in a container.
- A version bump is one line in the catalog, for the whole workspace.
- A fresh lockfile install checks release ages over the network, which is most of a cold image build
  (about 50 s; [deployment.md](../deployment.md)).
- A security fix published today cannot be installed until tomorrow without lowering the setting
  for that install.
- A new dependency with an install script fails the install until it is reviewed and added to
  `allowBuilds`.

## Alternatives considered

- **npm**: no catalogs, hoisted installs that allow undeclared imports.
- **Yarn (Berry)**: strict with Plug'n'Play, but PnP needs tool support this stack's tools do not
  all have, and its `node_modules` mode is hoisted.
- **Bun**: fast, with catalogs, but a package manager bundled with another runtime, while production
  and every tool here run on Node.
